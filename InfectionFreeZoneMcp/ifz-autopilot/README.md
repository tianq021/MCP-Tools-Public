# 无感染区本地小队自动控制设计

本地程序接管指定小队的例行搜刮和回仓，玩家继续操作保留队和聚落。DSH 负责处理玩家提问和自动控制遇到的例外。第一版只控制一支小队，正常运行期间的模型 API 调用为零。

## 第一版范围

- 自动查询附近建筑、派队搜刮、回仓卸货，再选下一栋。默认每搜一栋就回仓，便于验证回执和实际入仓。
- 实时在现有浮窗显示当前目标、订单结果和停止原因。玩家可以暂停自动下单、接管小队，或交给 DSH 临时处理。
- 第 6 天存档用 53 队作为验证例子，52 队归玩家。正式运行时从当前游戏会话读取分工，换档后重新确认。

## 技术选型与复用

| 部分 | 选型与用途 |
| --- | --- |
| 控制器 | 沿用仓库的 Node.js 和 JavaScript ES modules。在本目录放决策逻辑，由现有 Runtime 进程装配。用有限状态机推进每支小队的任务。 |
| 状态与地图 | 订阅 `StateService` 的 `state` 和 `event`。仅在需要选楼时，调用现有的 `nearbyScavengeQuery` 和 `readMapPage`。 |
| 游戏写入 | 通过 `ExecService` 提交 `scavenge_building` 和 `return_to_stockroom`。现有执行器负责会话校验、游戏写入租约、订单去重和回执核验。 |
| 浮窗与 DSH | 保留现有 Runtime 浮窗。订单进度走事件流，确实需要 DSH 判断的情况由 `Scheduler` 投递。 |
| 验证 | 复用仓库的 `node:test` 和 `FakeBridge`。先检查离线决策与回执处理，再用测试存档验证游戏内行为。 |

## 搜刮与回仓流程

| 游戏状态 | 控制器动作 |
| --- | --- |
| 队伍空闲且有货 | 优先回仓。核对小队背包，乘车时同时核对后备箱。 |
| 队伍空闲且空手 | 选附近可搜建筑，排除其他队的目标、靠近已知敌群的目标和近期已确认失败的目标。首选现有查询返回的近处候选，实际通行结果以订单回执为准。 |
| 搜刮结束 | 已搜完或确认只搜到一部分时，按实际载货量决定回仓还是继续选楼。订单受理后等待执行器确认结果。 |
| 回仓结束 | 再读一次载货量。现有回执可以证明货物减少，下一轮出发前须确认本轮货物已卸完。 |
| 小队低血或敌群逼近 | 停止派新搜刮单。核对当前订单后回仓，撤退受阻时请求接手。 |
| 游戏暂停、失焦、桥接离线或需要处理无线电 | 等待可操作状态。恢复时读取最新小队订单和游戏会话，再评估是否续派。 |
| 订单结果未知 | 记录并跟踪原请求 ID，沿用执行器的任务占用。连续确认失败时停止该队的自动派单，通知玩家或 DSH。 |

每队只保留一个待确认的任务。状态更新很频繁，选楼和提交用同一条串行流程。等待回执期间可以继续观察局势，确认没有合适目标时等局势或任务状态变化再试。Runtime 重启后，先核对游戏内仍在运行的订单，再决定是否派新单。 [地图筛选](../plugin/MapQuery.cs) · [订单回执](../runtime/exec-service.mjs)

## 接管与 DSH 唤醒

小队归属由 Runtime 记录。电脑、DSH 或玩家临时接管时，冻结该队旧控制方的新单，撤掉尚未提交的旧任务，再核对游戏中已存在的订单。已提交的订单继续跟踪，确需中止时走现有的停止接口。执行器在接收请求和实际下单前都核对归属，避免交接间隙提交旧任务。发现玩家手动改了订单时，先停止自动续派。交回电脑后从实时状态重新判断。 [协作规则](../AI游戏协作规则.md) · [停止与核实接口](../runtime/README.md)

例行的 `action_finished`、`order_completed` 和首次分工确认在本地处理，继续给浮窗显示订单进展。玩家发言、无线电需要选择、撤退受阻等需要判断的情况才唤醒 DSH。同一例外只提醒一次，直到出现新变化。唤醒消息带上小队、当前订单、失败原因和相关局势。 [现有调度器](../runtime/scheduler.mjs) · [游戏事件](../runtime/events.mjs)

## 实施与验收顺序

1. **只预览决策。** 先实现选楼、回仓、等待三种决策，输出原因。第 6 天快照中 53 队带两罐罐头，预期在恢复游戏后先回仓。快照处于暂停，适合检查决策，实际卸货需要在测试存档里确认。 [第 6 天游玩进度](../游玩进度-第6天.md)
2. **接通一支队的循环。** 用 `FakeBridge` 验证重复事件只提交一次、结果未知会保留占用、部分卸货后继续等。再用测试存档跑两轮完整搜刮回仓，确认货物入仓并记录下单和回执。
3. **接通临时接管。** 测试正常完工和玩家队回执只进浮窗，模拟一次异常唤醒 DSH，再验证接管前后的队伍归属。正常循环的验收指标是零模型请求，交接的验收指标是同一支队始终只有一方能提交有效订单。
