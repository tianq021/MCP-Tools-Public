# StartupWatch — 极轻量「开机启动项行为」记录器

> 2026-10-14 更新：开机闪窗排查改用专用 `BootCapture.exe`，安装、自测、日志位置和撤销方法见 [BOOT-CAPTURE.md](BOOT-CAPTURE.md)。安装结果以 `boot-install-status.json` 的 `State=Ready` 为准。下面保留的是旧版使用说明，其中“登录时抢先运行”“控制台进程就是黑框铁证”“少量进程证明沙箱限制”和“50ms 采样保证”等描述不成立，不能据此定案。旧版 Run 项在新模式安装成功后撤销；不要再运行旧 install.cmd 重复安装。

一个 30 KB 的单文件小程序，用来回答一个问题：

> **开机/登录之后，到底是哪个启动项在我的桌面上弹出了东西？**

它自己不弹窗、不常驻、不联网，采集完就退出。

---

## 为什么需要它

开机时「闪一下就没了」的黑框（cmd / PowerShell / ffmpeg 之类），往往在几百毫秒内结束，
用任务管理器、用 `Get-Process` 都抓不到，事后也没有日志可查。

StartupWatch 的做法是：在登录时抢先运行，在关键的头 20 秒里**每 50 毫秒**枚举一次进程表，
把每一个「新出生」的进程连同它的**父进程链**、**可执行文件路径**、**PE 子系统（GUI / 控制台）**
和**存活时长**记下来；同时把本机的全部自启项清单抓下来，最后做一张对照表。

它和普通监控工具的关键区别是：**它记录「存活时长」和「是不是控制台程序」**——
一个存活 61 毫秒、子系统为「控制台」、并且创建过 `conhost.exe` 的 `cmd.exe`，
就是那个「黑框一闪」的铁证。

## 安装

双击 **`install.cmd`**。它会往

```
HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run
```

写一条 `StartupWatch`，值形如 `"…\StartupWatch.exe" 120`。不需要管理员权限，
也会出现在「任务管理器 → 启动应用」里，可以随时在那里禁用。

想要**更早启动**（在资源管理器批处理 Run 键之前），双击 **`install-task.cmd`**
（它会自己弹 UAC 请求提权，因为计划任务必须管理员权限）：

```
schtasks /create /tn "StartupWatch" /tr "\"…\StartupWatch.exe\" 120" /sc onlogon /rl limited /f
```

它会创建一个「登录时触发」的计划任务。计划任务装不上也不影响 Run 键那条，两条可以同时存在
（两个实例各写各的时间戳日志，`latest.txt` 由后结束的那个覆盖）。

> 注意：注册表里记的是**绝对路径**，装好后请不要移动或删除本目录。

## 卸载

双击 **`uninstall.cmd`**（注册表项和同名计划任务都会删掉），日志文件保留。

## 怎么看结果

采集结束后打开 `logs\latest.txt`（每次运行还会另存一份带时间戳的副本）。
报告第 9 行是**运行环境自检**，先看它：

```
运行环境 : 会话=1  父进程=explorer.exe(pid13900)  首帧可见进程数=3  基线可见进程数=3  WMI可见进程数=？
```

* **可见进程数**：正常桌面会话应当是 **100 以上**。如果这里只有十几个甚至个位数，
  报告正文里会出现一整段 `!!! 警告`——**那次结果不可信**，别拿它下结论。
  原因是本程序被放进了沙箱 / 受限令牌（例如由某个受限终端或安全软件拉起），
  它对桌面上的普通进程几乎看不见。换成**从桌面直接双击**、或**以管理员身份运行**即可。
* 若同一行里 `WMI可见进程数` 很大而 Toolhelp 可见数很小，那就是**只有进程枚举被限制**，
  而不是系统真的很空 —— 这一条是程序自己用来区分「被限制」和「代码算错」的对照。

报告分四节：

**一、疑似「黑框一闪」的进程** ← 先看这里
控制台子系统且存活 < 3 秒的进程、创建过 `conhost.exe` 的进程，以及**启动时间与本工具几乎重合
（±5 秒）的控制台进程**（这类抓不到寿命，但正是登录瞬间那一批），附父进程链、路径、命令行。
还会单列「仅被事件追踪捕获」的极短进程（存活太短、轮询没采到）。

**二、本次采集窗口内新建的进程**
完整时间线：`时间 / 进程名 / pid / 存活时长 / 子系统 / 父进程`。

**三、自启项对照：哪些真的跑起来了**
逐条列出每个自启项（含启用/禁用状态）、它对应的可执行文件，以及本次是否真的观察到了它，
观察到的话给出存活时长和子系统。

**四、自启项清单（原始）**
注册表 `Run`/`RunOnce`（HKCU + HKLM + 32 位视图）、用户与公共启动文件夹（`.lnk` 会解析出真实目标）、
以及所有带「登录时 / 开机时」触发器的计划任务。

原始事件流另存为同名的 `.tsv`，字段以制表符分隔，便于自己写脚本分析：

```
HDR   运行头信息（时间、会话、父进程、可见进程数、WMI 是否可用、事件追踪是否可用）
INV   一个自启项        （来源 / 名称 / 状态 / 命令行）
PRE   启动前就已经在运行的进程（回溯 5 分钟内启动的）
NEW   本次新出生的进程  （时间 / 名称 / pid / ppid / 父进程 / 子系统 / 路径 / 命令行）
TRC   事件追踪捕获的进程（时间 / 名称 / pid / ppid / 父进程）
STP   进程结束          （时间 / 名称 / pid / 存活毫秒 / 父进程）
RPT   报告文件路径
```

## 用法（命令行）

```
StartupWatch.exe [秒数] [-o 输出目录]
```

* `秒数` 默认 `120`；采集节奏：前 20 秒每 50 ms 采样一次，20–60 秒每 200 ms，之后每 1000 ms。
* `-o` 指定日志目录，默认是程序所在目录下的 `logs`。

例：`StartupWatch.exe 60 -o D:\logs`

## 设计取舍与已知边界

* **没有任何依赖**：只用 .NET Framework 自带的 `kernel32`（Toolhelp 进程快照）和注册表 API，
  不依赖 WMI、不依赖 PowerShell、不依赖 VBScript（`VBScript` 在 Windows 11 25H2 已被微软列入弃用清单）。
* **进程枚举用 Toolhelp 而不是 WMI**：无需管理员权限，也不会因为 WMI 仓库异常而卡住。
* **第一帧抓得最早**：程序做的第一件事就是枚举一次进程表（在 WMI 探测、自启项枚举之前），
  并把这一帧单独保留。原因很实在：`ProbeWmi` 最多等 3 秒、自启项枚举可能更久，
  而这正是登录自启项集中启动的窗口；把枚举放在后面，等于自己把最关键的几秒变成盲区。
  自启项清单因此挪到**采集结束之后**再抓（清单在本次运行期间不会变）。
  所以「与本工具几乎同时启动」的进程即使已经退出，也仍然会出现在报告第一节里。
* **WMI 仅作为「可选增强」**，用来补命令行；探测带 3 秒超时，取命令行带 0.8 秒超时，
  **超时就永久降级**，绝不阻塞主循环（这台机器上曾有 WMI 调用长时间不返回的情况）。
* **事件追踪（`Win32_ProcessStartTrace`）是加分项**：零轮询、能抓到几十毫秒的进程，
  但在不少机器上（**含本机实测**）即使普通用户会话也不可用。不可用时会自动退回 50 ms 轮询——
  实测 50 ms 轮询已经能抓到存活 61 ms 的 `cmd.exe`。报告里会注明本次用的是哪种模式，
  不可用时也会明说「无法排除 <50ms 的极短进程」。
* **计划任务枚举走三条路**：优先 `Schedule.Service` COM API（不需要管理员），
  其次 `schtasks /query /v /fo CSV`，最后才是 `schtasks /query /xml`
  （`/xml` 需要管理员权限，普通会话下返回空，所以只作兜底）。
  日志里会有一行 `HDR tasks-source=COM / schtasks-csv / schtasks-xml / none`，
  明确告诉你这次清单是用哪条路拿到的；三条都失败会写一条显式的「清单获取失败」。
* **外部命令有硬超时**：读取 `schtasks.exe` 的输出带 15–25 秒超时并会在超时后杀掉子进程。
* **关于日志文件大小**：程序运行期间，资源管理器或 `Get-ChildItem` 可能把日志显示成 **0 字节**——
  这是 NTFS 对「正在被打开的文件」不即时更新目录项长度的正常行为，程序退出后才是最终大小。
  实测本程序确实会这样显示，别据此判断它卡住了。
* **隐私**：不联网、不上传、不写系统目录。日志只包含进程名、路径、命令行、父进程，
  全部落在你指定的 `logs` 目录里。
* **不常驻**：默认采集 120 秒后自行退出。若你希望整个会话都盯着，可以把秒数调大
  （例如 `3600`），此时 60 秒之后是每 1000 ms 采样一次，占用很低。
